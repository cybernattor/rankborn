# Rankborn — План исправлений

Сводный план по итогам трёх разборов: 3D-часть, управление и живой плейтест
(два клиента по сети, реальный ввод мыши и клавиатуры). Уже исправленное —
в истории коммитов; здесь только то, что осталось.

Порядок фаз — по ценности для плейтеста: сначала то, без чего игра не читается,
потом то, что делает её игрой, и только потом фундамент под фичи Foxhole.

> **Камера — принято: как у Foxhole, изометрия сверху** (см. [design.md, раздел 3](design.md#3-камера-как-у-foxhole--изометрия-сверху)).
> Код от первого лица уходит. Фаза 1.5 — прототип новой камеры и управления; всё, что зависит
> от камеры (анимации, вид оружия, HUD), делается уже под неё.

Обозначения: 🔴 баг, подтверждённый в игре · 🟠 недоделка · 🟢 новая возможность.
«Проверено» — как подтверждено, «Готово, когда» — критерий приёмки.

## Фаза 1. Баги из плейтеста — ✅ выполнена

Каждый пункт закрыт вместе с проверкой в `tests/spatial_check.gd` и перепроверен
живым прогоном (два экземпляра, ввод через `xdotool`).

| Было | Стало |
|---|---|
| Перекрестье улетало за экран при FPS < 16 (`lerp` с коэффициентом > 1) | Экспоненциальное сглаживание `1 - exp(-k·delta)` |
| В прицеле крест нарисован наполовину | Добавлены нижняя и правая линии |
| У жертвы брызги крови в полуметре от камеры — огромные кубы | У самой жертвы брызги не рисуются (о попадании ей скажет эффект урона из фазы 2) |
| Респавн со старым направлением взгляда — в край карты | При спавне и респавне взгляд к центру карты, голова прямо |
| Хост показывал `127.0.0.1` | Частные LAN-диапазоны, затем любой не-loopback IPv4. В обычной домашней сети баг и раньше не проявлялся — его вызвал нестандартный адрес тестового окружения, но запасной вариант был неверным |
| Одно лобби в списке дважды | Анонс несёт id сессии хоста; дубли схлопываются, предпочитается не-loopback адрес |
| «1/6» не обновлялось после входа | Это был замёрзший список: поиск останавливается при входе, а UI не очищался. Теперь очищается |
| Нет ника и выхода из лобби | Поле ника (сохраняется в `user://settings.cfg`), кнопка «Покинуть лобби», кнопка «Назад» на Android выходит из лобби |
| *Найдено попутно:* уход хоста не обрабатывался — клиенты зависали | `server_disconnected`: из лобби — обратно к поиску, из матча — в главное меню |
| Игроки появлялись в 4–13 м над землёй и падали с неба (маркеры на фиксированной высоте 10 м) | Высота спавна берётся с поверхности земли (`MeshUtils.terrain_height_at`); при респавне сначала перенос, потом «ожил» |

| Было | Стало |

## Фаза 3. Вертикальный срез войны (≈2–3 недели) — проверка главной гипотезы

Гипотеза: мета-игра Foxhole (снабжение → укрепление → захват) интересна на 2–4 игроках
за час. Если нет — ни полировка, ни масштаб не спасут, и это нужно знать до фазы 4.
Бой фазы 2 нужен срезу как обратная связь; остальное из фазы 4 ждёт результата.

| | Что | Готово, когда |
|---|---|---|
| 🟢 | **Каркас состояния войны (`WarState`)**: вся война — одна сериализуемая структура, единственный владелец — хост; склад, точки и постройки потом добавляются в неё, а не лежат переменными в узлах. Сразу маленький тест «сохранил → загрузил → совпало» | Тест проходит на пустой структуре; каждая следующая сущность ниже добавляет в `WarState` свой раздел и строку в тест. Иначе сохранение придётся вытаскивать из разбросанного состояния и переписывать |
| 🟢 | **База** у каждой стороны: респавн привязан к базе, а не к маркеру; у базы склад | Погибший возрождается на своей базе; склад хоста виден клиентам |
| 🟢 | **Снаряжение со склада**: на респавне — базовая винтовка и пара обойм (пол), остальное берётся со склада и там заканчивается | Пустой склад делает слабее, но не выкидывает из игры |
| 🟢 | **Один ресурс и один завод**: производит ящики по таймеру, пока ящик не вывезен — стоит | Ящик нельзя взять «из воздуха» |
| 🟢 | **Грузовик**: кабина с водителем, груз, физическая поездка завод → склад (после нескольких таких поездок склад пополнен) | Без доставки склад пустеет; перерезать дорогу — реальный ход |
| 🟢 | **Укрепления как объекты** (решение о траншеях — ниже): инженер ставит стену / мешки / участок траншеи за ресурс, постройка синхронизируется по сети и ломается | Поставленное видно у всех, коллизия и туман войны учитывают его |
| 🟢 | **Захват точки**: стоишь рядом — точка твоя; от владельца точки зависит, где респавн | Победа в войне — когда одна сторона держит заданное число точек; после неё мир сбрасывается и начинается новая война |
| 🟢 | Тактическая карта (минимум): фронт, свои базы/точки, метки | Открывается по кнопке, одинаково работает на таче |
| 🟢 | **Запись и загрузка войны**: хост пишет `WarState` в JSON при выходе и каждые N минут, читает при старте лобби. Делается после склада, точек и построек — до них писать нечего | Остановили матч, запустили снова — склад, точки и постройки на месте. SQLite — фаза 6, схема под реальное состояние |
| 🟢 | Лог метрик по типу ввода (K/D, попадания, время жизни) | Файл на хосте после матча; нужен, чтобы решать про aim assist по данным |
| ⏳ | **Плейтест среза вчетвером**: 1 час, два на два, с перезапуском посередине | Вердикт записать здесь: интересен ли цикл, кто возит и почему, сколько игроков нужно, чтобы склад не пустел |

**Критерий остановки.** Если на плейтесте возить грузовик никто не хочет или фронт
не двигается — срез переделывается (пол снабжения, награды за доставку, размер карты),
а фаза 4 не начинается.

### Решение: траншеи — объекты, а не деформация террейна (принято)

Было: фаза 5 планировала копать землю — чанки, `HeightMapShape3D`, сетевое состояние высот.
Стало: траншея — **стройобъект**, который инженер ставит на пологую землю, как у Foxhole
(там траншеи тоже готовые сегменты, а не вырытая яма).

Почему:
- деформация террейна — самая дорогая технология в проекте (меш, физика, сеть, туман войны,
  синхронизация при входе), а проверяет она ту же гипотезу, что и стена с мешками;
- ядро — механика «укрытие + туман войны + подавление», а не копание; её отлично проверяет объект;
- рельеф у нас и так пологий (4 м) именно для читаемости сверху — копать на нём нечего;
- объекты дёшево синхронизируются списком (тип, позиция, поворот, здоровье) и подходят и для P2P, и для dedicated server.

Что входит: сегмент траншеи — объект с коллизией по краям; игрок внутри — «лёжа/в приседе»
получает укрытие в полный рост, виден только вблизи (правило тумана войны).
Что откладывается: «лёжа» как состояние — вместе с сегментом траншеи, не раньше.
Деформация террейна — **не планируется**; вернуться к ней можно только если плейтесты покажут,
что объекты не дают нужной игры (тогда сначала прототип на одном квадрате).

### Конструктор оружия — отдельный короткий эксперимент (после среза)

Это второе заявленное отличие (design.md, раздел 1). Без проверки оно остаётся лозунгом.

| | Что | Готово, когда |
|---|---|---|
| 🟢 | 3 модуля (ствол, приклад, магазин), 2–3 параметра у каждого (разброс, скорострельность, вес) | Из модулей собирается винтовка, параметры читает `Rifle` |
| 🟢 | Правило баланса: сумма «очков» модулей ограничена, у каждого плюса есть минус | Нет сборки, которая строго лучше остальных (проверка скриптом по всем комбинациям) |
| ⏳ | Плейтест: разное ли играется | Если сборки сводятся к одной лучшей — конструктор вычёркиваем из дизайна и ищем другое отличие (design.md, раздел 1, вопрос 3) |

## Фаза 6. Масштаб и мета-игра поверх среза

Берётся только после вердикта фазы 3. Порядок — по вопросам, которые поставил срез.

| | Что | Почему важно |
|---|---|---|
| 🟠 | Dedicated server вместо P2P на 2–6 | Масштаб фронта (design.md, открытый вопрос 1). Туман войны на хосте — проверки видимости каждый с каждым (≈n²), на 64 игроках это тысячи лучей за тик: нужна сетка/ячейки и пределы по дальности. Сначала замер на ботах |
| 🟠 | Персистентность на SQLite: перенос сохранения из JSON (фаза 3), история, несколько миров | Схема строится по состоянию, которое уже есть и проверено |
| 🟢 | Ранги, полки, курсы обучения | Допуск к инструментам (метки, заказы). Второе отличие — после того как цикл среза работает |
| 🟢 | Инвентарь: слоты, вес, роль = снаряга | Разводит инженера, носильщика, медика |
| 🟢 | Несколько типов ресурсов, цепочки производства, ещё техника | Расширение цикла среза |
| 🟠 | Земля на чанках: только если число объектов или размер карты упёрлись в производительность | Не под траншеи — траншеи теперь объекты |
