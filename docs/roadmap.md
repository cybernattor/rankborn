# Rankborn — План исправлений

Сводный план по итогам трёх разборов: 3D-часть, управление и живой плейтест
(два клиента по сети, реальный ввод мыши и клавиатуры). Уже исправленное —
в истории коммитов; здесь только то, что осталось.

Порядок фаз — по ценности для плейтеста: сначала то, без чего игра не читается,
потом то, что делает её игрой, и только потом фундамент под фичи Foxhole.

> **Камера — принято: как у Foxhole, изометрия сверху** (см. [design.md, раздел 3](design.md#3-камера-как-у-foxhole--изометрия-сверху)).
> Код от первого лица уходит. Фаза 1.5 — прототип новой камеры и управления; всё, что зависит
> от камеры (анимации, вид оружия, HUD), делается уже под неё.

Обозначения: 🔴 баг, подтверждённый в игре · 🟠 недоделка · 🟢 новая возможность.
«Проверено» — как подтверждено, «Готово, когда» — критерий приёмки.

## Фаза 1. Баги из плейтеста — ✅ выполнена

Каждый пункт закрыт вместе с проверкой в `tests/spatial_check.gd` и перепроверен
живым прогоном (два экземпляра, ввод через `xdotool`).

| Было | Стало |
|---|---|
| Перекрестье улетало за экран при FPS < 16 (`lerp` с коэффициентом > 1) | Экспоненциальное сглаживание `1 - exp(-k·delta)` |
| В прицеле крест нарисован наполовину | Добавлены нижняя и правая линии |
| У жертвы брызги крови в полуметре от камеры — огромные кубы | У самой жертвы брызги не рисуются (о попадании ей скажет эффект урона из фазы 2) |
| Респавн со старым направлением взгляда — в край карты | При спавне и респавне взгляд к центру карты, голова прямо |
| Хост показывал `127.0.0.1` | Частные LAN-диапазоны, затем любой не-loopback IPv4. В обычной домашней сети баг и раньше не проявлялся — его вызвал нестандартный адрес тестового окружения, но запасной вариант был неверным |
| Одно лобби в списке дважды | Анонс несёт id сессии хоста; дубли схлопываются, предпочитается не-loopback адрес |
| «1/6» не обновлялось после входа | Это был замёрзший список: поиск останавливается при входе, а UI не очищался. Теперь очищается |
| Нет ника и выхода из лобби | Поле ника (сохраняется в `user://settings.cfg`), кнопка «Покинуть лобби», кнопка «Назад» на Android выходит из лобби |
| *Найдено попутно:* уход хоста не обрабатывался — клиенты зависали | `server_disconnected`: из лобби — обратно к поиску, из матча — в главное меню |
| Игроки появлялись в 4–13 м над землёй и падали с неба (маркеры на фиксированной высоте 10 м) | Высота спавна берётся с поверхности земли (`MeshUtils.terrain_height_at`); при респавне сначала перенос, потом «ожил» |

Первый тест APK на планшете — исправлено:

| Было | Стало |
|---|---|
| Поля ввода (ник, IP) и слайдеры не реагировали на касание | Эмуляция мыши из касаний включена; кнопки мыши сняты с игровых действий на тач-экране, чтобы касание не стреляло |
| В прицеле кнопки пропадали, но нажимались | Сенсорный UI и меню паузы — в `CanvasLayer` выше HUD |
| Правые кнопки разбросаны, свайп часто начинался на кнопке | FIRE в углу, DUCK/R/AIM/JUMP дугой вокруг неё; патроны над кнопками |
| Тень игрока ступенчатая | Дальность теней солнца 50 м вместо 100 (выше детализация вблизи); мягкость теней — по пресету графики |
| В лобби у игроков длинные числа (peer id) | Вместо id — пометки «хост» и «вы» |
| В прицеле не видно патронов и перезарядки | Патроны рисуются поверх затемнения прицела |
| Смерть выглядела как зависание: оружие пропадало, управление не отвечало | Экран смерти (кто убил, отсчёт до возрождения), камера падает к земле, HUD оружия скрыт |

Осталось из фазы 1:
- ❓ вертикальный шов цвета по центру экрана — проверить на реальной видеокарте;
- 🟠 после ухода хоста клиент попадает в меню без объяснения «хост завершил матч».

## Фаза 2. Обратная связь боя (≈3–4 дня) — минимум для любого плейтеста

Без этого игрок не понимает, попал ли он, попали ли в него и кто кого убил.

| | Что | Готово, когда |
|---|---|---|
| 🔴 | `damage_screen_effects.tscn` нигде не создаётся — эффекты урона мёртвый код | Подключено к локальному игроку, вспышка при уроне |
| 🟢 | Полоска здоровья | Видна в HUD, меняется по `health_changed` |
| 🟢 | Индикатор направления урона | Дуга вокруг персонажа в сторону стрелка |
| 🔴 | Килфид и счёт: `DeathmatchMode` шлёт `killfeed_entry` и считает очки, но UI нет | Килфид в углу, таблица счёта по Tab |
| 🟢 | Красный хитмаркер на убийство (сигнал есть, в игре не замечен — проверить) | Видно в плейтесте |
| 🟢 | Экран смерти: ✅ кто убил и таймер респавна; осталось «из чего» (оружие) и камера на убийцу | Показан всё время `DeadState` |
| 🟢 | Звуки: ✅ выстрел и затвор (синтез, 3D, слышны все стрелки, в том числе из тумана войны); ✅ шаги (решает хост, слышны из-за стен в радиусе 22 м, в приседе и с прицелом — тихо); осталось попадание, свист пуль рядом, перезарядка | Есть в `SFXManager`, 3D-позиционирование |
| 🟢 | Конец матча: лимит фрагов/времени → экран победителя → обратно в лобби | `has_winner()` реально используется |

## Фаза 3. Читаемость и карта (≈1 неделя)

| | Что | Готово, когда |
|---|---|---|
| 🔴 | Оружие висит на камере, а не в руках модели | Винтовка в руках модели (сокет руки), в т.ч. в приседе — сверху оружие видно только так |
| 🟠 | Удалённые игроки — статичные коробки без анимаций, движение рывками (нет интерполяции синхронизации) | Интерполяция позиции/поворота; простые анимации ходьбы/прицела/приседа (заменяют временное сжатие меша) |
| 🟠 | Свои и чужие сверху не различаются | Командные цвета + обводка (шейдер обводки уже есть) |
| 🟠 | Хедшот по высоте, а не по хитбоксу | Решить, нужны ли хедшоты при камере сверху (у Foxhole их нет); если нет — убрать |
| 🟢 | Карта пустая: ни укрытий, ни целей | ≥10 укрытий (камни, стены, окоп; первые — из прототипа камеры), 2 базы/точки захвата |
| 🟠 | Край карты — обрыв в серую пустоту | Визуальная граница: горы/вода/туман |
| 🟠 | Следы пуль — квады с z-fighting | `Decal` |
| 🟠 | Трассер — мигающий луч на всю длину | Летящий трассер |
| 🟠 | Нет пула частиц попаданий | Пул/переиспользование |

## Фаза 4. Управление — остатки

| | Что | Примечание |
|---|---|---|
| 🟠 | Переназначение клавиш | Экран настроек + сохранение раскладки |
| 🟠 | «Лёжа» | Делать вместе с траншеями (фаза 5) |
| 🟠 | Действие «взаимодействие» (E / Y) ни к чему не привязано | Появится с первым интерактивным объектом |
| 🟠 | Обзор свайпом на планшете неудобен (первый отзыв) | Снято решением по камере: свайп-обзор уходит, на таче будет правый стик направления стрельбы (фаза 1.5) |
| 🟠 | Подтормаживания на планшете | Замеры (FPS): Xiaoxin Pad 2024 — небо 60, земля 22, стрельба в землю 16–18; Redmi Pad Pro — небо 80–90, земля 54–65, стрельба 49–61. Узкое место — пиксели земли (тени, MSAA, разрешение) и вспышки света при стрельбе. Сделано: пресеты графики и режим «Авто» по умолчанию (старт со «Средней» на мобилках, снижение на ступень при среднем FPS < 45 за 5 с, только вниз), земля без бликов, вспышки света только на «Высокой». Готово, когда Xiaoxin держит ≥ 30 на «Средней» и ≥ 50 на «Низкой» — нужен повторный замер. Дальше, если мало: земля чанками (меньше рисуется за кадр) |
| ✅ | Рендерер на Android: Vulkan (Mobile) или OpenGL (Compatibility) | Замеры release-сборок (камера сверху): Redmi Pad Pro (Adreno 710), «Средняя» — Vulkan 97, OpenGL 85–89; Tecno Pova 7 Neo (Mali-G57 MC2), «Низкая» — Vulkan 58–60 (иногда 50), OpenGL 40–45. Vulkan быстрее на обоих — остаётся. Debug-сборка медленнее release примерно на 20 % (Redmi: 80 → 97): FPS меряем только на release |
| 🟠 | Tecno Pova 7 Neo упирается в 60 на «Низкой» | Проверить, не потолок ли это частоты экрана для приложения (часть телефонов отдаёт 120 Гц только играм из белого списка): FPS на «Средней» и «Высокой» — если тоже ровно 60, это потолок, а не производительность |
| 🟢 | Своя раскладка кнопок (перетаскивание, размер) | После того как раскладка двух стиков подтвердится в фазе 1.5 |
| 🟢 | Aim assist для тача/геймпада | Только после плейтестов на телефонах, правила — в [design.md](design.md#2-справедливость-кроссплея-пк-против-мобилок) |

## Фаза 5. Фундамент под мета-игру Foxhole

Камера решена (сверху); зависит от масштаба (design.md, раздел 1).

| | Что | Почему важно |
|---|---|---|
| 🟠 | Террейн: один меш + trimesh → чанки + `HeightMapShape3D` + сетевое состояние высот | Без этого траншеи невозможны. Решить заранее: heightmap (без нависаний) или воксели (блиндажи) |
| 🟢 | Траншеи (деформация террейна) + «лёжа» | Ядро позиционной войны |
| 🟢 | Строительство (фортификации, дороги) | Инженерная роль |
| 🟢 | Транспорт и логистика (грузовик, склад, доставка) | Ядро мета-игры Foxhole |
| 🟠 | Dedicated server вместо P2P на 2–6 | Масштаб фронта (design.md, открытый вопрос 1) |

## Как проверять

- `godot --headless --path . --script tests/spatial_check.gd` (+ сеть: `-- host` / `-- client`)
- `xvfb-run -a godot --path . --rendering-driver opengl3 --script tests/input_check.gd`
- Плейтест «как человек»: два экземпляра на разных Xvfb-дисплеях, ввод через `xdotool`,
  скриншоты через `import`. Так найдены все 🔴 из фазы 1–3.
- Каждый 🔴 закрывается вместе с проверкой в `tests/`, которая падает без исправления.
